| 028 | 2026-09-03 | `packages/claims/normalize.py` re-runs NFKC normalization *after* stripping punctuation, not just before | Trust one NFKC pass (before casefold/strip) to be sufficient | A hypothesis property test caught real non-idempotence: for input like `"C:\u0327"` (a base letter, a punctuation character, then a combining mark that was never adjacent to the letter), stripping the punctuation character creates a *new* adjacency between the letter and the combining mark that didn't exist in the original text — but without a second NFKC pass, that newly-adjacent sequence stays decomposed (`"c\u0327"`) instead of composing to `"ç"`.
